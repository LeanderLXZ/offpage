# 原始资料规范化

适用场景：

- 把 `txt / epub / pdf / html / 网页摘录 / 用户粘贴片段` 之类的原始资料，整理成 Offpage 的 source work package

使用方法：

- 把下面整段提示词发给一个全新的 agent
- 再补充真实输入路径、书名、作者信息或其他已知元数据

## 可直接使用的提示词

```text
你现在接手本地项目 Offpage，你没有任何额外背景知识，请完全按本提示词执行。

目标：
把我提供的一份或多份原始书籍资料，整理成这个项目的 source work package。

开始实质工作前，先做一次最小结构读取：

1. 先读 `prompts/shared/最小结构读取入口.md`
2. 再读 `README.md`
3. 如果你仍不确定 source package 与后续 `works/` / `users/` 的边界，再补读 `docs/architecture/data_model.md`
4. 如果这是更新已有 source package，而不是新建，先看现有 `sources/works/{work_id}/manifest.json`

你必须遵守这些目录边界：

1. `sources/works/{work_id}/` 只放原始导入、标准化正文、章节、metadata。
2. `works/{work_id}/` 是后续 canon 包，不要在这一步写入世界、角色、用户状态。
3. `users/{user_id}/` 是用户侧状态，这一步不要写。

你必须遵守这些语言与命名规则：

1. 如果作品是中文，`work_id`、书名、章节相关显示信息默认保持中文。
2. 中文作品不要为了方便而把作品名、地点名、角色名默认改成拼音。
3. 字段名和 schema key 可以保留英文，但作品内容相关的值优先中文。

你的任务步骤：

1. 先检查输入资料的格式与可用性。
2. 判定 `structure_mode`（先输出判定 + 依据 + 置信度，再决定是否继续）：

   扫描原始资料的顶层目录 / 文件名 / 目录页（epub TOC / pdf 大纲 / txt 章节标题模式）+ 前若干章正文样本，按以下两种格式之一判定：

   **monolithic**（单层、单卷、无子章节）
   - 整本书 = 一本小说，**没有"卷"概念**
   - 内部 = 多个章节平铺递进（"第 1 章" → "第 2 章" → …）
   - 章节内部 **不再细分** sub-section / 子章节
   - 层级结构：`book → chapters[]`（单层）
   - 典型形态：中文网络小说、单卷长篇小说
   - 识别信号：
     - 目录 / TOC 只有一级章节列表（"第 X 章" / "Chapter X"），**无"第 X 卷"分组**
     - 文件名 / 顶层目录 **不带卷号**（无 V01 / 卷一 / Volume 1）
     - 章节正文内 **没有** 稳定的小节分隔符（空行块 + 数字编号 / ◇◆※ / 场景切换符 等）

   **light_novel**（三层、多卷、每章再切子章节）
   - 整本书 = **≥ 2 个"卷"**（单卷的归 monolithic）
   - 每卷 = 多个"印刷章节"
   - 每个印刷章节 = 多个"sub-section / 子章节"（按段落分隔 / 数字编号 / 时间地点切分）
   - 层级结构：`book → volumes[] → chapters[] → sub_sections[]`（三层）
   - 典型形态：日式轻小说
   - 识别信号（**三条都满足才判 light_novel**）：
     - 卷分隔：epub 顶层目录按卷分目 / 文件名带卷号（V01 / 卷一 / Volume 1）/ 目录页含"第 X 卷"分组
     - 卷数 ≥ 2
     - 章内 sub-section：单卷内印刷章正文可识别稳定的小节分隔（空行块 + 数字编号 1./2./3. / 场景符 ◇◆※ / 时间地点切分如"——翌日清晨"）

   判定输出格式（**实质工作开始前必须先输出**，按以下结构逐行写）：

       structure_mode 判定：{monolithic | light_novel}
       判定依据：
         - 卷分隔信号：{有 / 无 / 不确定} — 证据：{具体引用，如"epub TOC 顶层有 5 个 OEBPS/Volume{N}/ 目录" / "文件名 V01.txt~V05.txt" / "目录页 line 3 '第一卷 邂逅'"}
         - 卷数：{N / 不适用（无卷分隔）}
         - 章内 sub-section 信号：{有 / 无 / 不确定} — 证据：{具体引用，如"第一章正文出现 4 处 '◇' 分隔" / "每章首段前有数字 1. 2. 3."}
       置信度：{0.0 ~ 1.0}

   决策规则：
   - 置信度 **≥ 0.8** → 把判定结果填入 `manifest.structure_mode`，继续下一步
   - 置信度 **< 0.8** → **停手**，把上面输出 + 不确定点列给用户，等用户明确回复 `monolithic` / `light_novel` 再继续；**不要擅自取默认值**或者强行往下做
   - 任意一条识别信号显示"不确定" → 置信度上限 0.7（即必走人工确认）
3. 为该书建立或更新 `sources/works/{work_id}/`。
4. 保留原始输入到 `raw/` 下的合适位置。
5. 把正文转成适合后续处理的规范化纯文本。
6. 如果能稳定识别章节，就写入 `chapters/C0001.txt` 这类标准化章节文件（文件名格式 `C####.txt`，4 位零填充，与 `chapter_id` 一致）。
7. 生成或更新这些元数据文件（每一份都必须过对应 schema；字段以 schema 为准，此处列出最关键的必填字段，方便记忆）：
   - `manifest.json`
     - Schema：`schemas/work/work_manifest.schema.json`
     - 必填：`schema_version`（当前 `"1.0"`）、`work_id`、`title`、`source_types`（数组，枚举值见 schema）、`ingestion_status`（规范化完成后填 `"normalized"`）
     - 建议填：`language`、`paths.{raw_root, normalized_root, chapter_root, scene_root, chunk_root, rag_root}`、`created_at`、`updated_at`
     - **`structure_mode`**（enum `monolithic` / `light_novel`，default `monolithic`）：
       - `monolithic`（默认）= 单卷非结构化作品（典型中文网络小说）：phase 0 token-budget chunking + phase 1 LLM stage 边界发现
       - `light_novel` = 多卷结构化作品（典型日式轻小说，卷 → 印刷章 → sub-section 三层结构）：1 sub-section = 1 C-id = 1 phase 0 chunk = 1 phase 1 stage，phase 1 stage_plan 1:1 程序化派生
       - 取值由 **task 步骤 2** 的判定流程产出（先输出判定 + 依据 + 置信度，置信度 ≥ 0.8 直接填，< 0.8 停手等用户确认）
       - **`structure_mode` 必须与 `metadata/chapter_index.json` items 的 `oneOf` profile 一致**（monolithic 不能含 6 个 light_novel 字段；light_novel 必填三层 seq + volume_id），不一致 `automation/ingestion/validator.py` 跨文件断言会报错
   - `metadata/book_metadata.json`
     - Schema：`schemas/work/book_metadata.schema.json`
     - 必填：`work_id`、`title`、`language`、`source_format`（枚举见 schema）、`chapter_count`、`created_at`、`updated_at`
     - 建议填：`author`、`identifier`、`original_drop_name`；EPUB 来源再加 `opf_path`、`cover_path`
   - `metadata/chapter_index.json`
     - Schema：`schemas/work/chapter_index.schema.json`（items `oneOf` 双 profile，与 manifest `structure_mode` 联动）
     - 顶层是数组，按 `sequence` 从 1 起严格连续递增
     - 全 profile 共有必填：`sequence`、`chapter_id`（格式 `^C[0-9]{4}$`，例如 `C0001`，后续 Phase 的交叉引用会依赖它）、`title`、`normalized_path`（例如 `chapters/C0001.txt`）
     - 全 profile 可选：`source_path`、`paragraph_count`、`char_count`
     - **monolithic profile**（`structure_mode = "monolithic"`）：禁止出现以下 6 个字段——`volume_id` / `volume_title` / `volume_seq` / `original_chapter_seq` / `original_sub_chapter_seq` / `original_chapter_title`（schema `additionalProperties: false`）。`title` 直接写章节标题。
     - **light_novel profile**（`structure_mode = "light_novel"`）：必填三层 seq 全部——
       - `volume_id`（格式 `^V[0-9]{3}$`，例如 `V001`）
       - `volume_seq`（整数 ≥ 1）：卷在全书的 1-based 序号（`V001` ⇒ 1，`V002` ⇒ 2，…）。与 `volume_id` 信息冗余但保留作 title 派生 / 排序整数源
       - `original_chapter_seq`（整数 ≥ 1）：原印刷章在所属卷的 1-based 序号；过卷重置（每卷起首回到 1）
       - `original_sub_chapter_seq`（整数 ≥ 1）：sub-section 在所属 original_chapter 的 1-based 序号；过原章重置（每原章起首回到 1）
     - light_novel profile 可选：
       - `volume_title`（卷名，例如 `第一卷 邂逅`；多个连续 sub-section 共享）
       - `original_chapter_title`（原印刷章名；多个连续 sub-section 共享）
     - **light_novel `title` 派生公式**：
       `title = f"{volume_title or '第N卷'} {original_chapter_title or '第M章'} {original_sub_chapter_seq}"`，其中 `N = volume_seq`、`M = original_chapter_seq`。缺失字段用占位字符串。
       - 例：`volume_seq=1`、`volume_title=None`、`original_chapter_seq=2`、`original_chapter_title=None`、`original_sub_chapter_seq=3` → `title = "第1卷 第2章 3"`
       - 例：`volume_title="邂逅"`、`original_chapter_title="月夜"`、`original_sub_chapter_seq=1` → `title = "邂逅 月夜 1"`
     - **light_novel sub-section 切分**：单卷内印刷章按段落分隔 / 数字编号 / 时间地点切分为若干 sub-section；每个 sub-section 一份 `chapters/C####.txt`、一条 chapter_index 记录；`chapter_id` (`C####`) 在全书递增，`sequence` 同步递增。
8. 如果资料无法可靠切章，不要硬拆；先说明阻塞点，并给出可执行的下一步建议。
9. 交付前强制自检：逐一 `python -c` 用 `jsonschema` 验证三份元数据通过 schema；或直接运行 `python -m automation.ingestion.validator <work_id>`；任意一份不过 schema，就退回步骤 7 修改，不得以 "已完成" 收尾。validator 会同时跨文件断言 `manifest.structure_mode` ⇔ `chapter_index` items profile 一致——不一致也算不过 schema。

输出要求：

1. 不要把大段原文直接粘贴进回答。
2. 不要默认通读整本书来做总结。
3. 回答里要明确：
   - 你创建或更新了哪些文件
   - 章节切分是否可靠
   - 还有哪些元数据是缺失或不确定的
   - 三份元数据文件是否已通过对应 schema 校验（必须明确说"已通过"或"未通过 + 原因"）
4. 如果你做了推断，要明确标注"这是推断"。

防漂移机制：

1. 开始执行前，先写一张“当前任务卡”：
   - 当前目标
   - 当前输入资料
   - 当前允许写入的目录
   - 当前禁止做的事
2. 不需要反复重读整份 prompt，但在以下时点必须回看本 prompt 的这些段落：
   - `目标`
   - `开始实质工作前，先做一次最小结构读取`
   - `目录边界`
   - `语言与命名规则`
   - `输出要求`
   - `防漂移机制`
3. 如果原始资料很多、格式很多，或单一文件很大，把”每个输入文件”或”每个转换阶段”视为单阶段，在阶段之间回看上述段落，确认未偏离目标。
4. 如果发现自己开始做”整本总结”或开始写入 `works/`、`users/`，立即停止，先重述任务卡，再继续。

我会补充给你以下输入：

- 原始资料路径：
- 书名：
- 作者（如果已知）：
- 语言（如果已知）：
- 其他说明：
```
