# 原始资料规范化 — 建立 / 更新 source work package

把一份或多份原始书籍资料整理成项目的 source work package（`sources/works/{work_id}/`）：原始导入 + 规范化正文 + 章节文件 + 三份 metadata，最后由 schema validation 硬门槛收尾。**本 prompt 只写 `sources/works/{work_id}/`**，不写 canon (`works/`) 或用户态 (`users/`)。

## Step 0: 最小结构读取

按以下顺序读到够用即止，不通读全仓：

1. `prompts/shared/最小结构读取入口.md`
2. `README.md`
3. 仍不确定 source ↔ canon ↔ user 边界 → `docs/architecture/data_model.md`
4. 若是更新已有包 → 现有 `sources/works/{work_id}/manifest.json`

## Step 1: 输入资料初检

- 列出输入文件清单 + 格式（epub / pdf / txt / 网页抓取等）
- 看目录页 + 文件名 + 顶层目录大致估章节数 / 卷数（不通读正文）
- 标记不可用 / 可疑文件，决定是否需要先停手向用户问清

## Step 2: 判定 structure_mode（决策卡 + 置信度门槛）

扫描原始资料的顶层目录 / 文件名 / 目录页（epub TOC / pdf 大纲 / txt 章节标题模式）+ 前若干章正文样本，按以下两种格式之一判定：

**monolithic**（单层、单卷、无子章节）

- 整本书 = 一本小说，**没有"卷"概念**
- 内部 = 多个章节平铺递进（"第 1 章" → "第 2 章" → …）
- 章节内部 **不再细分** sub-section
- 层级结构：`book → chapters[]`
- 典型形态：中文网络小说、单卷长篇小说
- 识别信号：
  - 目录 / TOC 只有一级章节列表（"第 X 章" / "Chapter X"），**无"第 X 卷"分组**
  - 文件名 / 顶层目录 **不带卷号**（无 V01 / 卷一 / Volume 1）
  - 章节正文内 **没有** 稳定的小节分隔符（空行块 + 数字编号 / ◇◆※ / 场景切换符等）

**light_novel**（三层、多卷、每章再切子章节）

- 整本书 = **≥ 2 个"卷"**（单卷的归 monolithic）
- 每卷 = 多个"印刷章节"
- 每个印刷章节 = 多个"sub-section / 子章节"（按段落分隔 / 数字编号 / 时间地点切分）
- 层级结构：`book → volumes[] → chapters[] → sub_sections[]`
- 典型形态：日式轻小说
- 识别信号（**三条都满足才判 light_novel**）：
  - 卷分隔：epub 顶层目录按卷分目 / 文件名带卷号（V01 / 卷一 / Volume 1）/ 目录页含"第 X 卷"分组
  - 卷数 ≥ 2
  - 章内 sub-section：单卷内印刷章正文可识别稳定的小节分隔（空行块 + 数字编号 1./2./3. / 场景符 ◇◆※ / 时间地点切分如"——翌日清晨"）

**决策卡输出格式**（Step 3 开始前必须先打印）：

```
structure_mode 判定：{monolithic | light_novel}
判定依据：
  - 卷分隔信号：{有 / 无 / 不确定} — 证据：{具体引用，如 "epub TOC 顶层有 5 个 OEBPS/Volume{N}/ 目录"}
  - 卷数：{N / 不适用（无卷分隔）}
  - 章内 sub-section 信号：{有 / 无 / 不确定} — 证据：{具体引用，如 "第一章正文出现 4 处 ◇ 分隔"}
置信度：{0.0 ~ 1.0}
```

**置信度门槛**：

- ≥ 0.8 → 把判定结果填入 `manifest.structure_mode`，进入 Step 3
- < 0.8 → **停手**，把决策卡 + 不确定点列给用户，等用户明确回复 `monolithic` / `light_novel` 再继续；**不要擅自取默认值**或强行往下做
- 任意一条识别信号显示"不确定" → 置信度上限 0.7（即必走人工确认）

## Step 3: 落盘原始资料 + 规范化正文

- 原始输入保留到 `sources/works/{work_id}/raw/<合适的子路径>`（不解压成 chunks，不重命名为拼音）
- 把正文转成适合后续处理的规范化纯文本（utf-8、去广告页 / 出版页 / 译者后记 / 导读等非正文）
- normalized 输出落 `sources/works/{work_id}/normalized/`（具体文件名按 manifest `paths.normalized_root` 约定）

## Step 4: 章节切分 → `chapters/C####.txt`

切分粒度由 Step 2 的 `structure_mode` 决定：

- **monolithic**：1 印刷章 = 1 `chapters/C####.txt`
- **light_novel**：1 sub-section = 1 `chapters/C####.txt`（印刷章内按段落分隔 / 数字编号 / 时间地点切分）

`chapter_id` 全书递增 4 位零填充（`C0001`、`C0002`、…），跨卷不重置；与 `chapter_index.json` 的 `sequence` / `chapter_id` 一致。

资料无法可靠切章 → **不要硬拆**；说明阻塞点，给出可执行下一步建议，停手。

## Step 5: 生成 / 更新三份 metadata

字段以 schema 为准；下方只列最关键必填项辅助记忆。

### `manifest.json`（schema：`schemas/work/work_manifest.schema.json`）

- 必填：`schema_version`（当前 `"1.0"`）、`work_id`、`title`、`source_types`（数组，枚举见 schema）、`ingestion_status`（规范化完成填 `"normalized"`）、`structure_mode`（enum `monolithic` / `light_novel`，由 **Step 2** 产出；schema 现强制必填，缺省 = schema 校验失败；必须与 `chapter_index` items profile 一致，Step 6 validator 跨文件断言）
- 建议填：`language`、`paths.{raw_root, normalized_root, chapter_root, scene_root, chunk_root, rag_root}`、`created_at`、`updated_at`

### `metadata/book_metadata.json`（schema：`schemas/work/book_metadata.schema.json`）

- 必填：`work_id`、`title`、`language`、`source_format`（枚举见 schema）、`chapter_count`、`created_at`、`updated_at`
- 建议填：`author`、`identifier`、`original_drop_name`
- EPUB 来源补：`opf_path`、`cover_path`

### `metadata/chapter_index.json`（schema：`schemas/work/chapter_index.schema.json`）

顶层是数组，按 `sequence` 从 1 起严格连续递增。items 用 `oneOf` 双 profile，与 `manifest.structure_mode` 联动。

**全 profile 共有**：

- 必填：`sequence`、`chapter_id`（`^C[0-9]{4}$`）、`title`、`normalized_path`（如 `chapters/C0001.txt`）
- 可选：`source_path`、`paragraph_count`、`char_count`

**monolithic profile**（schema `additionalProperties: false`）：

- 禁止出现 6 个 light_novel 字段：`volume_id` / `volume_title` / `volume_seq` / `original_chapter_seq` / `original_sub_chapter_seq` / `original_chapter_title`
- `title` 直接写章节标题

**light_novel profile**：

- 必填三层 seq：
  - `volume_id`（`^V[0-9]{3}$`，例 `V001`）
  - `volume_seq`（int ≥ 1）：卷在全书的 1-based 序号；与 `volume_id` 信息冗余但保留作 title 派生 / 排序整数源
  - `original_chapter_seq`（int ≥ 1）：原印刷章在所属卷的 1-based 序号；过卷重置
  - `original_sub_chapter_seq`（int ≥ 1）：sub-section 在所属 original_chapter 的 1-based 序号；过原章重置
- 可选：
  - `volume_title`（如 `第一卷 邂逅`；多个连续 sub-section 共享）
  - `original_chapter_title`（多个连续 sub-section 共享）
- **`title` 派生公式**：
  `title = f"{volume_title or '第N卷'} {original_chapter_title or '第M章'} {original_sub_chapter_seq}"`，其中 `N = volume_seq`、`M = original_chapter_seq`，缺失字段用占位
  - 例：`volume_seq=1, volume_title=None, original_chapter_seq=2, original_chapter_title=None, original_sub_chapter_seq=3` → `title = "第1卷 第2章 3"`
  - 例：`volume_title="邂逅", original_chapter_title="月夜", original_sub_chapter_seq=1` → `title = "邂逅 月夜 1"`

## Step 6: Schema validation（硬门槛）

**唯一收尾门槛 = validator 通过**：

```bash
python -m extraction.ingestion.validator <work_id>
```

通过条件（exit code `0`）：

1. 三份 metadata 均存在、JSON 合法
2. 三份均通过对应 schema
3. `book_metadata.chapter_count` == `len(chapter_index)`
4. `chapter_index.sequence` 严格 1..N 连续
5. `manifest.structure_mode` ⇔ `chapter_index` items profile 一致（monolithic 不含 6 个 light_novel 字段；light_novel 必填 4 个 seq 字段）

任意一条不过 → **退回 Step 5 修改，不得以 "已完成" 收尾**。

如需单文件临时检查，可用 `python -c "import json,jsonschema; jsonschema.validate(json.load(open('<file>')), json.load(open('<schema>')))"`，但收尾仍以 validator 为准（覆盖跨文件断言）。

## Step 7: 交付报告

明确说明：

- 创建 / 更新了哪些文件（路径列表）
- 章节切分是否可靠（按 structure_mode profile）
- 还有哪些 metadata 字段缺失或不确定
- **三份 metadata 是否已通过 validator 校验**：必须明确说"已通过（exit code 0）"或"未通过 + 具体错误清单 + 当前阻塞点"
- 哪些字段是推断得到（标注"这是推断"）

回答里**禁止**：

- 把大段原文直接粘贴
- 默认通读整本书做总结

## 写入边界（始终适用）

- `sources/works/{work_id}/` 只放：原始导入、规范化正文、章节、metadata
- `works/{work_id}/`（canon）和 `users/{user_id}/`（用户态）**本 prompt 一律不写**
- 一旦发现自己开始写 `works/` 或 `users/`，立即停手回查 Step 0 的最小结构读取

## 语言与命名规则

- 中文作品：`work_id` / 书名 / 章节相关显示信息默认保持中文
- 不要为了方便把作品名 / 地点名 / 角色名默认改成拼音
- 字段名和 schema key 可以保留英文，但作品内容相关的值优先中文
